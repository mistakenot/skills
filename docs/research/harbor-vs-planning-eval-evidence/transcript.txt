**Task 008: Session ID from Commit Message**

**Why this is useful:**
The auto-etl pipeline captures agent sessions and git commits as independent parquet datasets with no join key. Adding `session_id` to `model.Commit` makes them joinable, enabling queries like:
- Which session produced which commits?
- How many commits came out of a session?
- What was the agent doing before it committed?
- Which sessions produced zero commits?

The regex fallback matters for **historical coverage** — existing commits don't have a `Session-Id:` trailer, but many have a UUID somewhere in the message body (task IDs, worktree branch names, handoff references).

**What the requirements specify:**
- New `SessionID string` field on `model.Commit` (parquet: `session_id,dict`)
- Pure helper `extractSessionID(messageBody, trailersJSON string) string` with fallback chain:
  1. Check `trailers_json` for `Session-Id` key → use trailer value
  2. `regexp` scan message body for first standard UUID
  3. Return `""` if neither matches
- Trailer always wins over body UUID (precision over recall)
- 5 unit tests, genstats counter, no external dependencies
- `CommitFile` / `CommitHunk` denormalization is explicitly out of scope

**Open question** (gates the doc): Is `Session-Id` the agreed trailer key name, and will the harness begin including it automatically in future sessions?
